# Resume Cheat Sheet

Quick reference for building a tech resume that passes ATS filters and
reads well for humans, including FAANG targeting tips.

## Core Concepts

- **ATS**: Applicant Tracking System — software that parses resumes and
  filters on keywords and structure.
- **Keywords**: Exact terms from the job description present in your resume.
- **Recruiter Scan Time**: ~6-8 seconds per resume. Front-load impact.
- **Bullet Formula**: Action verb + context + impact metric.
- **Resume vs CV**: Resume is a 1-page marketing doc; CV is a full record.

> Your resume exists to get an interview, not to tell your whole life
> story. Save details for the conversation.

## Quick Reference Tables

### Section Order (Chronological)

| Order | Section | Purpose |
|-------|---------|---------|
| 1 | Name + Contact | Clear identity, links |
| 2 | Summary (optional) | 2-3 lines for senior roles |
| 3 | Skills / Tech keywords | ATS match catcher |
| 4 | Experience | Main evidence, newest first |
| 5 | Projects | Proof of building things |
| 6 | Education | Degrees, GPA (if strong) |
| 7 | Certifications / Awards | Extras near the tail |

> For students and new grads, put Projects before Experience if you have
> little work history, and lead with Education for assists.

### Keyword Optimization

| Source | How to Use |
|--------|-----------|
| Job description | Mirror exact tool names and verbs |
| Company stack | List frameworks you used, even at a low level |
| Role title | Match "Consultant", "Engineer", "SDE..." |
| Avoiding spam | Repeat the tool naturally, not a keyword salad |

### Action + Impact + Metric Formula

```
{Action verb} {context/what} -> {measured impact}
```

Good vs weak bullets:

| Weak | Strong |
|------|--------|
| "Worked on the login feature" | "Built OAuth login, cutting support tickets 30%" |
| "Used Docker" | "Containerized 8 services, reducing deploy time 5x" |
| "Helped the team" | "Shipped feature that lifted NPS by 4 points" |
| "Responsible for testing" | "Added 200 tests, catching 90% of regressions in CI" |

## Common Patterns / Action Verbs

```
Built  Reduced  Drove  Launched  Automated  Migrated  Optimized
Scaled  Designed  Architected  Refactored  Engineered  Led  Mentored
```

### Sample Bullets

- "Rebuilt checkout flow in React; conversion rose 12% in one quarter."
- "Designed a Kafka pipeline moving 5M events/day; latency dropped 60%."
- "Automated release with CI/CD; deploys cut from 40 min to 6 min."
- "Mentored 3 juniors; 2 promoted to mid-level within a year."
- "Wrote regression suite (pytest); reduced escaped bugs by 35%."

## Do's and Don'ts

| Do | Don't |
|----|-------|
| One page (2 max for 10+ yrs) | Going over 2 pages |
| Tailored bullets per job | Sending one generic resume |
| Quantify everything you can | Empty claims, vague verbs |
| Standard fonts and sections | Images, tables, graphics for ATS |
| PDF export | Word-only or unusual formats |
| Honest, ownable impact | Exaggeration that backfires |
| Custom URL on links | Broken GitHub/LinkedIn links |

## ATS Tips

- Use standard headings: `Experience`, `Education`, `Skills`.
- Avoid tables, text boxes, columns, and header/footer text.
- Save as PDF (or plain text); scripts parse PDFs best.
- Spell out and abbreviate key terms: e.g. `CI/CD (Continuous Integration)`.
- Put dates in a clear format like `Jan 2024 - Present`.
- Run your resume through a test ATS or parser before applying.
- Match the job's exact tool names (`Kubernetes`, not `k8s`).

> If the ATS cannot parse it, no human ever sees it. Simplicity wins.

## Tailoring for FAANG / Big Tech

- Emphasize scale: traffic, data volume, latency, uptime, users reached.
- Show system design and ownership, not just task execution.
- Use the reverse-chronological format they expect.
- List languages they use (Java, Go, Python, C++), prominently.
- Keep bullet focus on *metric* results, one per line.
- Prepare a matching story for each bullet; interviewers will probe.

## Common Mistakes

- Objective statements like "seeking a challenging role" — waste of space.
- Front-loading soft skills without evidence (team player, hard worker).
- Unreadable fonts or 6-column graphics that defeat ATS.
- Typos — recruiters treat them as a quality signal.
- Listing responsibilities instead of outcomes.
- Gaps with no explanation ready for the interview.
- Every bullet starting with the same verb ("Developed... Developed...").
- Including irrelevant jobs from 15 years ago.
